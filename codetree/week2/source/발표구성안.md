# 최종 발표 구성안

## 0. 표지

- 목적: 발표 주제와 풀이 방향을 먼저 보여준다.
- 포함 내용:
  - 연산자 배치하기
  - 문제 분석, 알고리즘 선택, 설계 흐름 중심 풀이
  - DFS, Backtracking, Brute Force

## 1. 문제 소개: 문제 상황

- 사용 이미지: `문제사진.png`
- 목적: 문제에서 요구하는 조건을 먼저 정리한다.
- 문제 링크: https://www.codetree.ai/ko/frequent-problems/samsung-sw/problems/arrange-operator/description

  - `n`개의 숫자가 주어진다.
  - 주어진 숫자 사이에 연산자를 배치한다.
  - 가능한 식의 최솟값과 최댓값을 구한다.
  - 계산은 연산자 우선순위 없이 앞에서부터 차례대로 진행한다.

## 2. 문제 소개: 예제로 이해하기

- 사용 이미지: `입력 예제.png`
- 목적: 연산자 배치에 따라 결과가 달라지는 것을 예제로 보여준다.
- 강조할 내용:
  - 숫자의 순서는 바꿀 수 없다.
  - 바꿀 수 있는 것은 숫자 사이에 들어갈 연산자의 순서다.
  - 연산자 우선순위는 적용하지 않고 앞에서부터 계산한다.
  - 같은 숫자와 연산자 개수가 주어져도 배치 순서에 따라 최솟값과 최댓값이 달라진다.

## 3. 문제 분석: 제한 조건

- 목적: 입력 크기를 보고 탐색 가능성을 판단한다.
- 포함 내용:
  - 입력 크기: `2 <= n <= 11`
  - 각 숫자: `1` 이상 `100` 이하
  - 시간: `1초`
  - 메모리: `80MiB`
- 결론:
  - 입력 크기가 작다.
  - 연산자는 최대 `n - 1`, 즉 최대 10개만 배치하면 된다.
  - 모든 연산자 배치를 확인하는 방향을 생각할 수 있다.

## 4. 사용한 알고리즘

- 목적: 내가 선택한 풀이 도구를 먼저 선언한다.
- 화면 방향:
  - 숫자 사이의 빈칸에 연산자를 배치하는 그림 추가
  - Brute Force, DFS, Backtracking을 카드 형태로 배치
- 사용한 알고리즘:
  - DFS, 재귀 방식
  - Backtracking
  - Brute Force

## 5. 사용한 이유

- 목적: 왜 이 알고리즘들이 이 문제에 적합한지 설명한다.

### Brute Force

- 적용할 수 있는 연산자의 개수는 최대 10개다.
- 각 자리에 최대 3가지 연산자를 선택할 수 있다.
- 따라서 경우의 수 상한은 `3^10 = 59,049`다.
- 대략 계산하면 `81 * 81 * 9 < 100 * 100 * 10 = 100,000`이다.
- 1초에 약 1억 번 정도를 기준으로 보면 충분히 정답을 찾을 수 있다.
- 실제 경우의 수는 각 연산자의 사용 횟수가 정해져 있으므로 이보다 더 적다.

### DFS / Backtracking

- 첫 번째 연산자부터 하나씩 대입하는 구조와 잘 맞는다.
- 현재까지 계산한 값과 남은 연산자 개수만 관리하면 된다.
- 재귀 깊이가 최대 10에서 11 정도라 메모리 부담이 작다.
- 구현이 단순하다고 판단했다.
- 구현하기 쉬운 방식이라고 판단했다.

## 6. 사용하지 않은 알고리즘과 이유

- 목적: 다른 선택지를 검토했지만 사용하지 않은 이유를 설명한다.

### BFS

- 사용할 수 있는 연산자의 횟수가 정해져 있다.
- 각 상태마다 연산자 사용 현황을 관리해야 한다.
- 큐에 중간 상태를 저장해야 한다.
- 단순 계산으로도 `100,000 * 10` 정도의 상태 관리가 필요하다.
- 메모리 한도 안에는 들어오지만, DFS에 비해 얻는 이점이 작다.
- 최단거리 문제가 아니므로 BFS의 장점이 크지 않다.
- 현재 탐색 중인 경로만 관리하는 DFS에 비해 이점이 작다고 판단했다.

### DP

- DP로 풀려면 더 작은 문제로 쪼개고 관계식을 찾아야 한다.
- 하지만 누적 계산값과 남은 연산자 개수가 상태에 들어간다.
- 그 결과 점화식과 상태 관리가 복잡해진다.
- 입력 크기가 작으므로 완전탐색이 더 빠르고 단순하다고 판단했다.
- 작은 입력에서는 빠르게 푸는 것이 더 중요하다고 판단했다.

## 7. 설계 흐름

- 목적: DFS와 백트래킹이 실제로 어떤 순서로 동작하는지 설명한다.
- 화면 방향:
  - 상태 정의와 탐색 흐름을 나누어 배치
  - 흐름은 `선택 -> 계산 -> 감소 -> 재귀 -> 복구 -> 반복` 형태로 시각화

### 종료 조건

- 모든 연산자를 사용했으면:
  - 최솟값과 최댓값을 갱신한다.
  - 현재 탐색을 종료한다.
- 코드에서는 모든 숫자를 사용해 `depth == N`이 되었을 때를 종료 조건으로 둔다.

### 탐색 과정

1. 각 단계에서 사용할 연산자를 선택한다.
2. 선택한 연산자로 현재 값과 다음 숫자를 계산한다.
3. 남은 연산자 개수를 갱신한다.
4. 다음 단계로 재귀 호출한다.
5. 재귀 호출이 끝나면 선택한 연산자 개수를 복구한다.
6. 다시 다른 연산자를 선택하며 반복한다.

## 9. 풀면서 조심해야 했던 지점

- 사용 이미지: `처음에 실수한것.png`
- 목적: 실제로 실수한 부분과 구현 시 주의할 부분을 정리한다.
- 화면 방향:
  - 실수 가능 지점 3개를 더 크게 강조
  - 내가 실제로 한 실수는 보조 정보로 배치

### 내가 실제로 한 실수

- 연산자 입력을 숫자 개수 `N`만큼 받으려고 했다.
- 하지만 연산자 종류는 `+`, `-`, `*` 3개이므로 3번만 입력받아야 한다.

### 실수할 수 있는 지점

- 재귀 시작 조건:
  - 연산하려면 두 숫자가 필요하다.
  - 따라서 처음 숫자를 `cur`로 넣고 `dfs(arr[0], 1)`에서 시작해야 한다.
- 백트래킹 시:
  - 사용한 연산자 개수를 반드시 원상복구해야 한다.
- 최댓값과 최솟값 초기 설정:
  - 최댓값은 충분히 작은 값으로 초기화한다.
  - 최솟값은 충분히 큰 값으로 초기화한다.
  - 이때 초기값은 가능한 탐색 결과 범위 밖에 있어야 한다.
