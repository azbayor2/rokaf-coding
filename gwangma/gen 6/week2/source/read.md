- 문제: https://www.codetree.ai/ko/frequent-problems/samsung-sw/problems/arrange-operator/description - 연산자 배치하기
- 문제 설명
  - 3개의 연산자가 있고 (+, -. *), 각 연산자마다 사용 횟수가 정해져 있음
  - n개의 숫자가 주어짐
  - 주어진 숫자 사이에 연산자를 배치함
  - 이때 최솟값, 최댓값을 구함
  - 단, 계산은 앞에서부터 차례대로 진행

- 분석
  - 제한 조건
    - 입력 크기: 2 ≤ n ≤ 11
    - 각 숫자는 1이상 100 이하
    - 시간: 1초
    - 메모리: 80mib
  - 알고리즘: dfs(재귀방식), back tracking, brute force
  - 사용 이유:
    - brute force
      - 적용할 수 있는 연산자의 개수는 10개임
      - 그러면 각 자리에 3가지의 경우가 가능하므로 3^10 가지가 존재
      - 3^10은 대충 81*81*9 < 100*100*10 = 100,000 가지가 존재 (물론 상한선 기준으로 계산 했기 때문에 실제 횟수는 더 적음)
      - 즉, 1초 (1억번) 안에 정답을 찾을 수 있음
    - dfs/back tracking
      - 첫번째 연산자부터 하나씩 대입하기때문에, 백트래킹이 적합하다고 판단
      - 재귀 깊이가 최대 10~11개이기 때문에 메모리 초과 걱정 없음
      - 구현하기 쉬움 (개인적인 판단)
  - 사용하지 않은 알고리즘
    - BFS
      - 사용할 수 있는 연산자의 횟수가 정해져 있어, 각 노드별로 연산자의 사용 현황을 관리할 필요가 있음
      - 단순 계산을 했을 때 100,000*10 (경우의 수 * 상태관리를 위한 배열의 크기) 만큼의 크기가 필요하고, 메모리 한도 내에 있음
      - 현재 탐색하는 노드의 상태만 관리하면 되는 DFS에 비해서 이점이 이점이 없어서 사용 안함.
      - 그리고 보통 BFS는 최단 거리를 구할 때 사용하기 때문에 이 문제에 사용하기에는 적합하지 않음.
    - DP
      - DP로 풀기 위해서는 더 작은 문제로 쪼개야 하고, 이를 통해 관계식을 찾을 필요가 있음
      - 점화식이 굉장히 복잡함, 작은 숫자에서는 빠르게 푸는 것이 중요하다고 생각해서 안씀

- 설계
  - 만약에 모든 연산자를 사용했으면
    - 최대값/최소값 갱신
    - 탈출
  - 만약에 최대 레벨이 아니면
    1. 각 단계에서 연산자를 선택
    2. 선택한 연산자로 계산
    3. 남은 연산자의 개수 갱신
    4. 다음 단계로 재귀호출
    5. 재귀 호출이 끝나면 선택한 연산자 개수 복구
    6. 1번으로 가서 다른 연산자로 반복

- 실수 지점
  - 재귀 시작 조건
    - 연산을 하기 위해서는 두개의 숫자가 있어야 하기 때문에, 처음 재귀를 시작할 때 처음 숫자를 재귀 입력값으로 설정함.
  - 백트래킹 시
    - 백트래킹 할 때 사용한 연산자의 횟수를 원상복구 해야 함.
  - 최대값/최소값 초기 설정
    - 최대값은 작은 숫자로, 최솟값은 큰 숫자로 설정할 필요가 있음
    - 이 때 설정하는 숫자는 탐색 범위 밖이어야 함.
